# 2026-10-04 工作日志

## 诊断：/user/userLogin 返回 500 Whitelabel Error Page

**项目**：A-simple-shop（Spring Boot 3.5.9 + Java 17 + MyBatis-Plus 3.5.12 + Shiro + MySQL）

**现象**：浏览器访问 `/user/userLogin` 返回 `Whitelabel Error Page, status=500`。

**实测证据（未改项目代码，全部为只读/临时副本验证）**：
- MySQL 正常：3306 在监听，库 `a-simple-shop` 存在，表 `user`(id INT, name VARCHAR(50), password VARCHAR(50))，数据 `id=1, name=cyr, password=123456`（明文）。
- 用 `mvn dependency:build-classpath` + `java -cp target/classes;<cp>` 启动应用（占位端口 18080），请求接口复现：
  ```
  org.apache.shiro.UnavailableSecurityManagerException:
    No SecurityManager accessible to the calling code, either bound to
    org.apache.shiro.util.ThreadContext or as a vm static singleton.
    at org.apache.shiro.SecurityUtils.getSecurityManager(SecurityUtils.java:123)
    at org.apache.shiro.SecurityUtils.getSubject(SecurityUtils.java:56)
    at UserController.userLogin(UserController.java:24)
  ```

**根因**：`shiro-spring-boot-starter` 用的是 **1.9.0**，与 Spring Boot 3 不兼容。
1. 1.9.0 的 jar 里只有 `META-INF/spring.factories`，没有 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`；Spring Boot 3.0 起不再读 spring.factories 的 EnableAutoConfiguration → **Shiro 全部自动配置失效**。
2. 1.9.0 基于 `javax.servlet`，SB3 是 `jakarta.servlet`（Tomcat 10.1.50）。
- 后果：没有 ShiroFilter 注册、`SecurityUtils` 里的静态 SecurityManager 从未被绑定 → 第一行 `SecurityUtils.getSubject()` 即抛异常；UserController 只 catch `AuthenticationException`，抓不住 → 冒泡成 500。

**已验证的修复方案**（在 `%TEMP%\shop-shiroupgrade` 副本上实测，未动主项目）：
1. pom 里 `shiro-spring-boot-starter` 1.9.0 → **3.0.1**（本机 .m2 已有全套 3.0.1，且其 jar 带 `AutoConfiguration.imports`）。
2. `MyRealm.java` 的 import 改一行：`org.apache.shiro.util.ByteSource` → `org.apache.shiro.lang.util.ByteSource`（Shiro 2.0+ 把该类挪到了 shiro-lang）。其余 import（`org.apache.shiro.spring.web.config.DefaultShiroFilterChainDefinition`、`org.apache.shiro.web.mgt.DefaultWebSecurityManager`、`org.apache.shiro.realm.AuthorizingRealm` 等）包路径不变。
- 结果：编译通过、启动正常、Shiro 过滤器链生效（堆栈里出现 AbstractShiroFilter/ProxiedFilterChain），500 消失。

**修复后暴露的第二个问题（尚未处理）**：返回 `HTTP 200 + {"code":500,"msg":"登录失败"}`，堆栈为
`org.apache.shiro.authc.IncorrectCredentialsException`。
原因：DB 里是明文 `123456`，而 ShiroConfig 配了 `HashedCredentialsMatcher(md5, iterations=1)`、MyRealm 又传了盐 `ByteSource.Util.bytes("yuqn")` → 比对的是 md5 摘要而非明文，永远不相等。需要二选一：去掉密码加密匹配（明文比对），或把库里密码改成加盐 md5 的值。

**备注**：本机 Bash 工具环境残缺（`ls/tail/find` 找不到），改用 Python 子进程 + subprocess 驱动 Maven/Java 完成全部探测。

## 续：主人自行升级到 shiro 3.0.1 后的两个新问题

**状态**：pom 已改 `3.0.1`，`MyRealm` import 已改 `org.apache.shiro.lang.util.ByteSource`，编译通过。

### 问题 A：浏览器"重定向次数过多"

在副本上启动实测（端口 18082），逐跳打印 Location：

```
/            -> 302  Location=/login.jsp;jsessionid=xxx
/index.html  -> 302  Location=/login.jsp;jsessionid=xxx
/login.jsp   -> 302  Location=/login.jsp;jsessionid=xxx   ← 自己重定向到自己
/error       -> 302  Location=/login.jsp;jsessionid=xxx
/user/userLogin?name=cyr&pwd=123456 -> 200 {"code":500,"msg":"登录失败"}
```

**根因**：`/**` = authc 兜底规则把 Spring Boot 内置的 `/error` 也拦了。`loginUrl`（默认 `/login.jsp`）页面并不存在 → 404 → 容器内部转发 `/error` → 又被 authc 拦 → 302 回 `/login.jsp` → 死循环。
即 `/login.jsp` 那条 302 是"anon 放行后 404、404 转发 /error、/error 被拦"的结果，不是 anon 没生效。

**认知纠正**：不是"Shiro 3.0.1 默认全部拦截"——Shiro 不会自动生成 `/**` 规则；是项目自己写的兜底定义在 1.9.0 时代从未生效，升级后才暴露。

**已验证的修复**（副本实测，端口 18083）：在 `/**` 之前补 anon 规则后 `/`→200、`/index.html`→200、接口→200 JSON、不再循环：

```java
addPathDefinition("/error","anon");      // 关键，不加则任何 404/500 都会变循环
addPathDefinition("/","anon");
addPathDefinition("/*.html","anon");
addPathDefinition("/static/**","anon");
addPathDefinition("/favicon.ico","anon");
```

### 问题 B：密码策略不匹配（解释向）

DB 存明文 `123456`，但配了 `HashedCredentialsMatcher(md5, iterations=1)` + 盐 `ByteSource.Util.bytes("yuqn")`。
Shiro 会把用户提交的明文算成摘要再与 DB 里的字符串比 → 永远不等 → `IncorrectCredentialsException`。

**关键细节**：Shiro `SimpleHash` 内部是 `digest.update(salt)` 后才 `digest.digest(source)`，
哈希顺序是 **盐在前、密码在后**。已算出参考值：
- `md5("yuqn" + "123456")` = `d9d29476fe3fc6ae73386b1b86c377e6`
- `md5("yuqn" + "cyr")` = `8c9ee33226145efd668cc5e19d72d917`

两条路线：A) 去掉 credentialsMatcher 走明文比对；B) 把库里密码换成上面的摘要（正规做法）。
