### 设计决策与理由
1. **`LogoutController` 单独建类**：因为类级 `@RequiresRoles` 会作用到 `UserController` 所有方法，而退出登录不应要求任何角色（会话过期时也要能优雅返回）。主人要求注解不动 → 用「新建独立 Controller」绕过。
2. **`userInfo` / `revise` 从会话取身份**，不用请求参数传用户名 —— 防止越权查/改他人。
3. **`userInfo` 返回前把 `password`、`salt` 置 null** —— 安全底线。
4. **`updateUser` 改密码时重新生成随机盐**，盐与摘要成对更新（沿用 `PasswordHelper` 既有方案）。
5. **改名会查重**，被他人占用则返回失败。
6. `LogoutController` 同时定义 `@RequestMapping("/user")` + `@GetMapping("/userLogout")`，最终路径 `/user/userLogout`。

## 追加3：新建全局异常兜底类（2026-10-14）

### 需求
主人要求新建一个 `@RestControllerAdvice` 兜底类（明确说先不管 Filter 层未登录的问题）。

### 改动（仅新建 1 个文件）
- **新建** `handler/GlobalExceptionHandler.java`（新建 `handler` 包）

未改动任何已有文件。

### 实现内容
4 个 `@ExceptionHandler` 方法：

| 异常 | 返回 |
|---|---|
| `UnauthenticatedException` | `Result(401, "未登录，请先登录", null)` |
| `UnauthorizedException` | `Result(403, "权限不足", null)` |
| `AuthorizationException`（兜底） | `Result(403, "权限校验失败", null)` |
| `AuthenticationException` | `Result(401, "用户名或密码错误", null)` |

- 用 `new Result(code, msg, null)` 构造（未改 `Result.java`，未加静态方法）。
- 未加 `@ExceptionHandler(Exception.class)` 全兜底 —— 避免调试期吞掉真实堆栈。
- 未加 `@ResponseStatus` —— 只改 JSON 业务码，HTTP 状态仍 200。

### 验证状态
- ✅ `mvn -o compile` **EXIT=0**。
- ⚠️ **运行时效未验证**（本地环境无法启动 Spring Boot）。

### 重要结论（本轮讨论得出）
**未登录（`authc` 过滤器拦截）的异常，`@RestControllerAdvice` 兜不到。** 原因：
- `authc` 在 **Filter 层**主动拒绝（重定向或 401），请求根本没进 DispatcherServlet。
- `@RequiresRoles` 的异常在 **MVC 层 AOP** 抛出才能被兜住。
- 只有"已登录但角色不足"这条路径，异常才在 MVC 链内，advice 才生效。

三条处理未登录的路线（供后续参考）：
- A. 自定义 `JsonAuthcFilter extends FormAuthenticationFilter`，重写 `onAccessDenied` 返回 401 JSON（推荐，但 Shiro 3.0 starter 的注册方式需验证）
- B. 把 `authc` 改 `anon` 让请求进 Controller 靠注解拦（有"未加注解的接口裸奔"风险）
- C. 外层再包一个 Filter 包装 response

主人当前决定：**先不管 Filter 层，只加 advice 兜底类。**

### 环境限制（反复出现，值得记住）
当前 bash shim 环境下无法启动 Spring Boot：
- `mvn spring-boot:run` 后台拉起失败（进程秒退、日志 0 字节）
- `java -cp` 直接跑同样秒退
- `mvn package` 离线缺 `spring-boot-loader-tools`、`spring-boot-buildpack-platform`（pom 里 repackage 执行点仍存在，虽然 `<skip>true</skip>` 在 configuration 上）
- **可用**：JDK 17 在 `C:\Program Files\Eclipse Adoptium\jdk-17.0.20.101-hotspot\bin\java.exe`；MySQL 可用 `mysql -h127.0.0.1 -uroot -p123456`（Python subprocess + gbk 解码）
- 结论：**编译验证可做，端到端 HTTP 验证需主人在 IDE 里跑**

- 所有响应（含非 2xx）原始打印到日志区 → **可直接验证 `@RestControllerAdvice` 是否生效**
- 纯原生 JS，无框架依赖；XSS 转义（`esc` 函数）
